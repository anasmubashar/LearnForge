# LearnForge AI Customer Support Assistant

An AI-powered customer support assistant built for **LearnForge** (an online ed-tech platform). Grounded strictly in company knowledge-base documentation (course FAQs, platform policies, and past resolved support tickets), the assistant reduces hallucination, resolves conflicting/superseded policies, tracks answer confidence, and automatically escalates to human agents when confidence is low or when queries fall outside the knowledge domain.

---

## Data Schema

Documents, chunks, and metadata are indexed in **Qdrant Cloud** under the collection `learnforge_kb` using 3072-dimensional cosine vectors.

### Qdrant Point Schema (`PointStruct`)

```json
{
  "id": 8392183928192,
  "vector": [0.0142, -0.0521, 0.0819, "... (3072 float values)"],
  "payload": {
    "doc_id": "FAQ-02",
    "doc_type": "faq",
    "source_file": "faqs.md",
    "title": "Can I get a refund for a course?",
    "last_reviewed": "February 2026",
    "has_outdated_warning": true,
    "document": "### FAQ-02: Can I get a refund for a course?\n\nEligible individual course purchases may be refunded within 14 days of purchase...\n\nIMPORTANT: An older version of this FAQ stated refunds were available within 7 days. That wording is outdated and has been replaced by the 14-day policy."
  }
}
```

### Schema Field Definitions

| Field | Type | Description |
| :--- | :--- | :--- |
| `id` | `uint64` | Stable integer hash derived from `doc_id` (`MD5(doc_id)[:16] % 2^63`). |
| `vector` | `List[float]` | 3072-dimensional embedding generated by `models/gemini-embedding-001`. |
| `doc_id` | `string` | Canonical document identifier (e.g., `FAQ-01`, `POLICY-03`, `TICKET-12`). |
| `doc_type` | `enum` | Categorization: `"faq"`, `"policy"`, or `"ticket"`. |
| `source_file` | `string` | Origin file (`faqs.md`, `policies.md`, `tickets.md`). |
| `title` | `string` | Extracted Markdown headline of the chunk. |
| `last_reviewed`| `string` | Date/month stamp extracted from the text (e.g. `"February 2026"`). |
| `has_outdated_warning` | `boolean` | Flagged by regex parser if the chunk contains references to superseded versions. |
| `document` | `string` | Full textual content of the chunk provided as context to the LLM. |

## Failure Handling

Production support assistants face three primary operational hazards: poor retrieval, hallucination on low-confidence queries, and stale or contradictory knowledge. Here is how LearnForge AI resolves each:

### 1. Bad Retrieval & Out-of-Domain Queries
- **Problem**: When a user asks something completely outside LearnForge's domain (e.g., *"How do I fix a flat tire on a bicycle?"* or obscure legal questions), vector search will still return the nearest semantic neighbors.
- **Solution**:
  - We calibrated the baseline cosine similarity of `gemini-embedding-001`. Unrelated text produces cosine similarity of `~0.50–0.56`, whereas relevant queries produce `> 0.68–0.85`.
  - We enforced `SIMILARITY_ESCALATE_THRESHOLD = 0.60`. If the highest retrieval score is `< 0.60`, the system automatically flags `escalate = True` and sets the reason: *"The closest knowledge-base match has low relevance. A human agent can better assist."*

### 2. Low-Confidence Answers & Hallucination Suppression
- **Problem**: LLMs often hallucinate plausible-sounding answers when context only partially answers the prompt.
- **Solution**:
  - **Grounding Prompt**: The system prompt instructs Gemini 3.5 Flash Lite to answer *only* using information provided in the context chunks and explicitly penalizes ungrounded speculation.
  - **Self-Reported Confidence Score**: The model outputs structured JSON with a float `confidence` score (0.0 to 1.0) and a `confidence_reason`. The prompt anchors confidence strictly to *context adequacy*, not refusal confidence.
  - **Gating Threshold**: If `confidence < 0.50` (or if structured JSON fails to parse), the system triggers human escalation.
  - **Transparent UI**: The UI displays the exact confidence percentage and reason to the user, ensuring full transparency.

### 3. Stale Data & Conflicting Policy Resolution
- **Problem**: Policies change over time (e.g., LearnForge migrated from a 7-day refund window to a 14-day window; certificate rules were clarified). Chunks in the KB often reference older wording.
- **Solution**:
  - **Regex Detection during Ingestion**: Patterns like `"older version"`, `"that wording is outdated"`, and `"no longer applies"` tag chunks with `has_outdated_warning: true`.
  - **Prompt Hierarchy**: The LLM prompt explicitly commands: *"If a context chunk says that older information is outdated or replaced, always prefer the NEWER guidance and clearly state the correction."*
  - **UI Disclaimer & Badge**: Answers drawing upon flagged sources receive a `"Stale Data Filtered"` indicator and a callout warning advising the learner to contact support if something diverges on their screen.

## Evaluation Plan

To measure answer quality, retrieval precision, and hallucination rates systematically, we implement an evaluation pipeline based on **RAGAS** (Retrieval Augmented Generation Assessment) paired with human rubric grading:

### 1. Automated Metrics (RAGAS Framework)

```
                            ┌────────────────────────┐
                            │  Evaluation Dimensions │
                            └───────────┬────────────┘
                ┌───────────────────────┴───────────────────────┐
                ▼                                               ▼
     [Retrieval Quality]                              [Generation Quality]
  • Context Precision: % of                        • Faithfulness: % of claims in
    retrieved chunks that are                        the answer directly supported
    actually relevant.                               by the context (Hallucination Rate = 1 - Faithfulness).
  • Context Recall: % of golden                    • Answer Relevance: How well the answer
    reference chunks retrieved                       addresses the user's actual question.
    in Top-K.
```

- **Faithfulness (Target: > 98%)**: A secondary evaluator model extracts all factual claims from the answer and verifies if each claim is entailed by the retrieved chunks. Hallucination rate is defined as `1.0 - Faithfulness`.
- **Answer Relevance (Target: > 92%)**: Measures semantic alignment between the question and the generated answer, penalizing verbose or evasive responses.
- **Context Precision & Recall (Target: > 90%)**: Evaluates whether the top-5 retrieved chunks contain the necessary ground-truth facts.

### 2. Golden Test Dataset (50 Curated Scenarios)
A benchmark dataset is maintained with three classes of test cases:
1. **Direct In-Domain (30 queries)**: Standard FAQs, account management, video playback rules.
2. **Adversarial / Stale Policy (10 queries)**: Queries asking specifically about 7-day refunds, expired voucher rules, or superseded policies. Target: 100% correct resolution of the newer policy.
3. **Out-of-Domain / Negative (10 queries)**: General knowledge, competitor questions, or unanswerable requests. Target: 100% escalation rate.

### 3. Human-in-the-Loop Eval Rubric
Support team leads grade 100 randomly sampled live conversations weekly using a 4-point rubric:
- **Grade 4 (Accurate & Complete)**: Fully factual, concise, correctly resolved policy conflicts.
- **Grade 3 (Minor Incompleteness)**: Correct facts, but missed a minor nuance.
- **Grade 2 (Over-Confident / Vague)**: Answered without sufficient context; should have escalated.
- **Grade 1 (Hallucination)**: Fabricated facts or stated superseded policy.

## Trade-offs & Architecture Decisions

| Decision | Chosen Option | Considered Alternatives | Rationale & Trade-offs |
| :--- | :--- | :--- | :--- |
| **Vector DB** | **Qdrant Cloud** | Pinecone, ChromaDB, pgvector | **ChromaDB** required MSVC C++ compilers not available on Windows without build tools. **pgvector** requires managing a PostgreSQL cluster. **Qdrant** provides a clean REST/gRPC client, pre-built Windows wheels, native hybrid search support, and free cloud hosting with zero infrastructure overhead. |
| **LLM** | **Gemini 3.5 Flash Lite** | Claude 3.5 Sonnet, GPT-4o | Gemini 3.5 Flash Lite provides sub-second time-to-first-token, exceptionally low cost per query (~$0.075 per million tokens), and natively supports structured JSON schema output with strict context grounding. |
| **Embeddings** | **Gemini `models/gemini-embedding-001`** | Sentence-Transformers (`all-MiniLM-L6-v2`) | `sentence-transformers` requires PyTorch, which is a 2.5 GB dependency requiring C++ compilation on newer Python runtimes. Using the Gemini Embedding API yields high-dimensional (3072-dim) semantic fidelity without local hardware bottlenecks. |
| **Session Memory** | **In-Memory Dict (`defaultdict`)** | Redis, PostgreSQL | For a take-home prototype, an in-process dictionary keeps the project zero-dependency and easy to evaluate with `uvicorn`. In a multi-replica production deployment, this would be replaced with Redis with TTL expiration. |
| **Chunking** | **Structural Markdown (`---`)** | Fixed Token Window (e.g. 500 tokens with overlap) | LearnForge's KB documents are already structured into atomic, self-contained units (individual FAQs, policy sections, tickets). Preserving whole chunks prevents splitting critical caveat sentences away from their parent policies. |

## Quick Start & Setup Guide

### Prerequisites
- Python 3.10+ (tested on Python 3.11, 3.12, 3.14)
- Node.js 18+ and npm
- A Google Gemini API key ([Google AI Studio](https://aistudio.google.com/))
- Qdrant Cloud cluster or local Qdrant instance

---

### 1. Backend Setup

```bash
cd backend

# Create and activate virtual environment
python -m venv venv
# On Windows:
.\venv\Scripts\activate
# On macOS/Linux:
source venv/bin/activate

# Install dependencies
pip install -r requirements.txt

# Configure environment variables
# Copy .env.example to .env and fill in your keys:
# GEMINI_API_KEY=your_gemini_key
# QDRANT_URL=https://your-cluster.aws.cloud.qdrant.io:6333
# QDRANT_API_KEY=your_qdrant_key

# Run Knowledge-Base Ingestion (embeds and stores 40 chunks in Qdrant)
python ingest.py

# Start the FastAPI server
uvicorn main:app --reload --port 8000
```

The API will be live at `http://localhost:8000`. Interactive OpenAPI documentation is available at `http://localhost:8000/docs`.

---

### 2. Frontend Setup

```bash
cd frontend

# Install Node dependencies
npm install

# Start Vite dev server
npm run dev
```

Open `http://localhost:5173` (or the port displayed in your terminal, e.g. `http://localhost:5174`) in your browser to interact with the assistant.

## API Reference

### `POST /chat`
Submits a user message and returns the RAG response with confidence and citations.

**Request Body:**
```json
{
  "session_id": "c7a8b9e0-1234-5678-90ab-cdef12345678",
  "message": "What is the refund policy for courses?"
}
```

**Response Body:**
```json
{
  "session_id": "c7a8b9e0-1234-5678-90ab-cdef12345678",
  "answer": "LearnForge allows refunds within 14 days of purchase...",
  "confidence": 0.95,
  "escalate": false,
  "escalation_reason": null,
  "has_outdated_sources": true,
  "sources": [
    {
      "doc_id": "FAQ-02",
      "doc_type": "faq",
      "source_file": "faqs.md",
      "title": "Can I get a refund for a course?",
      "snippet": "Eligible individual course purchases may be refunded within 14 days...",
      "relevance_score": 0.755,
      "has_outdated_warning": true
    }
  ]
}
```

### Other Endpoints
- `GET /sessions/{session_id}`: Retrieve multi-turn chat history.
- `DELETE /sessions/{session_id}`: Clear session state.
- `POST /admin/reingest`: Trigger on-demand re-ingestion of the knowledge base.
- `GET /health`: Health probe.
